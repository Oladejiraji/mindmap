# Mindmap
## Collaborative Research Infrastructure

# Overview

Mindmap is evolving from a branching chat application into a collaborative research system built around spatial reasoning, live collaboration, and persistent research graphs.

The product is designed for teams conducting research together in real time through interconnected nodes that represent investigations, ideas, summaries, debates, and outputs.

The system combines:

- collaborative workspaces
- node based knowledge organization
- AI assisted research
- persistent context inheritance
- multiplayer collaboration
- graph based synthesis

The closest mental model is:

> Figma for collaborative research and reasoning.

The graph is not navigation around the product.

The graph is the product.

---

# Product Vision

Research is naturally nonlinear.

Teams investigating complex subjects constantly:

- split into subtopics
- explore tangents
- compare findings
- test hypotheses
- revisit earlier conclusions
- synthesize results
- merge insights

Traditional software forces this process into:

- documents
- chat timelines
- folders
- tabs
- isolated conversations

Mindmap treats research as a living graph of connected investigations.

Every node represents a unit of reasoning.
Every branch represents a line of inquiry.
Every collaborator contributes to the evolving research topology.

The resulting graph becomes:

- the workspace
- the memory system
- the research process
- the deliverable

---

# Core Principles

## 1. Spatial Research

Research should exist visually in space.

Users should be able to:

- see investigations evolve
- understand relationships between ideas
- identify active areas of work
- follow reasoning paths
- compare parallel explorations
- synthesize conclusions spatially

The interface should communicate structure immediately without requiring explanation.

---

## 2. Parallel Thinking

Multiple collaborators should be able to investigate different branches simultaneously without interfering with one another.

Each branch isolates a line of inquiry while preserving inherited context.

This enables:

- independent exploration
- focused investigations
- cleaner reasoning
- contextual continuity
- collaborative divergence

Branching is infrastructure for parallel thinking.

---

## 3. Persistent Research Lineage

The graph preserves the evolution of reasoning over time.

Every branch maintains:

- inherited context
- contributor history
- research provenance
- synthesis relationships
- decision lineage

This creates a transparent record of how conclusions were formed.

---

## 4. Multiplayer Collaboration

Collaboration is a foundational primitive.

The system is designed for:

- teams
- organizations
- researchers
- designers
- engineers
- analysts
- strategists
- multidisciplinary groups

Realtime collaboration should feel natural and ambient.

Users should always understand:

- who is active
- where people are working
- what investigations are live
- what branches are evolving

---

## 5. AI Assisted Research

AI models are embedded into the workspace as research collaborators.

The system should support:

- multiple models
- node specific models
- specialized agents
- synthesis workflows
- automated branching
- summarization
- comparison
- structured output generation

Models should feel integrated into the graph rather than centralized in a chatbot interface.

# The Graph Model

## Research Nodes

Every node represents a research unit.

A node may contain:

- conversations
- files
- citations
- summaries
- generated outputs
- AI responses
- annotations
- tasks
- references
- linked investigations

Nodes can:

- branch
- merge
- inherit context
- stream updates live
- reference other nodes
- participate in synthesis

---

## Branches

Branches represent independent lines of inquiry.

When a branch is created:

- it inherits parent context up to the branch point
- future parent changes do not affect the branch
- collaborators can investigate independently
- reasoning remains isolated and traceable

This creates clean parallel investigations without losing context.

---

## Synthesis Nodes

Synthesis nodes aggregate findings from multiple investigations.

They are responsible for:

- summarizing branches
- reconciling conclusions
- comparing evidence
- identifying contradictions
- generating outputs
- producing final deliverables

Synthesis nodes become convergence points within the graph.

They should likely appear visually distinct from standard research nodes.

# Interface Direction

# The Graph Is The Workspace

The graph should remain continuously visible.

Users should interact directly with the research topology rather than navigating between isolated pages.

The interface should feel closer to:

- Figma
- graph tooling
- multiplayer IDEs
- spatial operating systems

Than:

- chat applications
- threaded messaging
- static documents

The canvas itself becomes the primary interaction layer.

---

# Node Design

Nodes should be:

- compact
- scannable
- composable
- information dense

Each node should communicate:

- title
- owner
- activity state
- connected branches
- model usage
- synthesis state
- research progress
- citations or assets attached

The system must scale visually to large research graphs containing many simultaneous investigations.

---

# Presence And Activity

Collaboration should feel spatial and live.

Examples include:

- collaborator labels attached to nodes
- live research indicators
- streaming updates
- active branch states
- realtime presence
- branch creation feedback

The workspace should feel computationally active.

---

# Model Visibility

AI model usage should appear inline within the graph.

Each node may:

- use different models
- invoke specialized agents
- run synthesis workflows
- coordinate multiple reasoning systems

Model metadata should communicate orchestration and specialization without becoming the central interface.

---

# Activity Density

Over time the graph itself should communicate:

- active investigations
- stale branches
- unresolved questions
- highly referenced nodes
- validated conclusions
- AI generated exploration
- collaborator concentration

This can be represented through:

- subtle motion
- streaming indicators
- edge highlighting
- activity states
- density visualization
- presence indicators

# Architectural Direction

The original architecture remains highly aligned with the new product direction.

Key strengths include:

- append only history
- immutable reasoning lineage
- contextual inheritance
- branch isolation
- reactive updates
- adjacency list graph structure
- streaming support
- deterministic layout

These characteristics support:

- provenance
- replayability
- auditability
- synthesis traceability
- collaborative reasoning history

The graph structure naturally scales from conversation trees into organizational research infrastructure.
